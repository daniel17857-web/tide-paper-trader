### R2-01 風險契約定錨實際成交價(sizing 與 RR 於成交時重算)

- **來源**:mechanism R2-01 + rigor R2-03 + minimal R2-01 三方共識合併;稽核修正全數吸收。
- **對應問題**:S4。`core/risk.py:18` 以 `plan.entry_ref`(訊號K收盤)計 stop_dist 定部位,`core/broker.py:56-72` 實際以次K開盤±滑價成交;第一輪 31/40 筆(77.5%)實際風險偏離名目 >10%(gap_ratio 0.35~2.61),7 筆 target 出場無一落在計畫 1.5~2R 區間(實際 0.147~4.323R);MIN_RR 僅計畫階段檢查、成交後無人把關。「每筆 1% 風險」名存實亡,R 刻度整體失控。
- **修訂內容**:
  1. **sizing 移至成交時點**:`risk.check()` 保留熔斷/曝險/重複標的檢核與「預估 size>0」檢查,改為核發「資格」單(size 待定);`broker._try_fill()` 取得 actual_entry(次K開盤±不利滑價)後計 size,公式沿用 risk.py 現行三式、僅將分母 stop_dist 改為 |actual_entry−stop|。**USDJPY 分子乘數維持 stop**(size = 資金×RISK_PCT×stop/|actual_entry−stop|),保證停損出場經換匯後恰為資本 1%——稽核A明示:若誤把分子也換成 actual_entry,停損實虧 = 1%×(entry/stop) ≠ 1%,是最易寫出 sizing bug 之處。
  2. **前視防範**:size 的輸入僅限成交K的 open(成交瞬間已知)、成交前已定的 stop、當時資本;禁止引用成交K的 high/low/close;以對照 fixture 強制。
  3. **fill-time RR 複檢**:(target−actual_entry)×d / ((actual_entry−stop)×d) < MIN_RR → 不進場,reason=`rr_degraded_at_fill`(統一碼,原 not_filled_rr 併入)。只少做、不多做,方向保守。
  4. **不新增參數**(沿用 RISK_PCT、MIN_RR);MAX_ENTRY_GAP_R 不採納(見第 5 節)——朝目標方向跳空由本票 RR 複檢封閉,朝停損方向跳空由 R2-02 成交時檢核封閉,兩票綁定採納。
  5. `scripts/run_pipeline.py:32` PENDING_COLUMNS 之 size 欄語義調整:pending 單僅存風控預檢用預估值(或留空),實際 size 於成交時決定;fixture 須涵蓋跨執行 pending 單成交。
  6. SPEC AC-11 措辭由「進場價」明定為「實際成交價」。台帳新欄併入 R2-07。
- **驗收條件**:
  - Given 任一 fixture 計畫且次K開盤相對 entry_ref 任意跳空(含 USDJPY、含 738 點級極端跳空)/ When 成交後觸發停損 / Then 台帳 risk_actual 欄 = 該軌當時資本×RISK_PCT(誤差 <1%);以名目停損價計之虧損 = 資本×RISK_PCT(誤差 <1%);因本輪同時採納 R2-03,實際入帳虧損 = 資本×RISK_PCT×(1+出場滑價/停損距離)(誤差 <1%)。
  - Given 僅成交K之 high/low/close 不同、open 相同的兩份 fixture / When 計算 size / Then 兩者 size 完全一致(證無前視)。
  - Given 跳空使 fill-time RR < MIN_RR / When `_try_fill` / Then 不進場且 rejects.csv 記 `rr_degraded_at_fill`。
  - Given 第一輪型態之 fixture 全量重播 / When 重算 / Then 停損出場筆中不存在實際風險偏離名目 >10% 者。
  - Given 跨執行的 pending 單於次日成交 / When 撮合 / Then size 於成交時以 actual_entry 計定,且上列條款全部成立。
- **預期影響**:1% 風險契約與 R 刻度恢復可信——第二輪一切 R 統計有意義的前提;0.147R 式失真 target 與 2.6 倍名目風險極端單(09-17 跳空 738 點事故)不再可能。十二票中優先級最高:不修它,每筆新樣本都繼續被壞尺污染。
- **風險/副作用**:RR 複檢減少成交、樣本累積更慢;交易母體改變 → 與第一輪不可比(本就歸零);不利跳空時 size 變大、名目曝險上升(風險金額固定 1%,模擬允許小數口;曝險檢核為筆數制,已核對無對 size 的依賴)。保守偏差:量尺修復,方向中性偏保守。
- **實作成本**:中(core/risk.py、core/broker.py、core/models.py 之 Order、scripts/run_pipeline.py、tests、SPEC AC-11 改寫)。

### R2-02 滑價占比上限門檻(planner 預檢 + 成交時複檢,兩段式)

- **來源**:mechanism R2-02 + rigor R2-04 + minimal R2-03 三案合併(數學等價);依稽核B修訂採兩段式,成交時檢核為主體;參數名統一。
- **對應問題**:S1+S2。2 pips 固定滑價佔 1h 停損距離中位數 22.5%、最高 69%;19 筆 tech/1h 中 16 筆滑價占比 >10%,累計拖累 4.103R = 該組總虧損 89.3%;1h 停損中位數僅 8.9 pips,7/19 筆 tech/1h 進場當根 −1R。根因是停損距離相對摩擦太小,R 量尺被滑價污染——這類交易量到的是摩擦模型,不是訊號。
- **修訂內容**:
  1. config.py 新增**單一常數、單一名稱**:`MIN_STOP_SLIP_RATIO = 10.0`(停損距離須 ≥ 10×單邊滑價,等價於滑價 ≤ 停損距離 10%;原三案 MIN_STOP_SLIPPAGE_RATIO / MAX_SLIP_RATIO / MIN_STOP_SLIP_RATIO 統一為此名;數值 10 為設計推導之污染上限 0.1R,凍結前由 Daniel 定案,見 D-02)。
  2. **planner 階段預檢**:以 entry_ref 計停損距離 < 10×滑價 → rejected(reason=`stop_too_tight`),早期過濾、拒單原因乾淨。
  3. **成交階段複檢**:`_try_fill` 以實際 entry 檢 |actual_entry−stop| ≥ 10×滑價,不足則不進場(reason=`stop_too_tight_at_fill`)——封閉「計畫通過但開盤朝停損方向跳空使實際距離縮小」的漏洞(現行跳空保護只擋「越過停損」,不擋「貼近停損」;R2-01 的 RR 複檢在該方向反而變好、擋不住)。
  4. 不得以拉遠停損硬湊(改變訊號語義且屬調優)。**三不改聲明**:滑價參數不調降、同K雙觸發以停損計不動、進場當根檢查不動。門檻值寫入 prereg,禁止用第一輪損益反推;第一輪 fixture 重播定位為**撮合迴歸測試**,非調參。
- **驗收條件**:
  - Given 停損距離 = 9.9×滑價的計畫 / When planner / Then rejected(`stop_too_tight`);Given = 10.0×滑價 / Then 通過此檢查。
  - Given 計畫階段通過(entry_ref 計距離 = 12×滑價)、次K開盤朝停損方向跳空使實際距離 = 9×滑價 / When `_try_fill` / Then 不進場且記 `stop_too_tight_at_fill`。
  - Given 第一輪 7 筆「進場當根 −1R」1h 案例之行情 fixture 重播 / When 套用新門檻 / Then 其中停損距離 <10×滑價者全數於計畫階段被拒、不產生交易。
  - Given 第一輪 19 筆 tech/1h fixture 重播 / Then 被擋筆數與人工驗算完全一致(依第一輪數據預期約 16 筆)。
  - Given 全 repo / Then `MIN_STOP_SLIP_RATIO` 僅定義於 config.py 一處(grep 可測)。
- **預期影響**:摩擦主導的微停損單從源頭消失(而非靠放寬規則掩蓋);留下的 1h 樣本滑價占比與 1d 同數量級,1h vs 1d 對照才有意義;估計 1h 成交量約減八成,1d 幾乎不受影響(1d 滑價占比約 3.9%)。
- **風險/副作用**:樣本累積更慢;tech/1h 可能近乎無交易——這本身就是「該週期在 2 pips 摩擦假設下不可做」的誠實答案;本票機械性改善帳面(拒掉一整類預期虧損交易),必須綁定 R2-06 歸零+prereg 機制推導聲明,嚴禁與第一輪混算比較。
- **實作成本**:小(planner/broker 各數行 + config 一參數 + 測試)。

### R2-03 出場滑價(stop 與 invalidated 出場加不利滑價)

- **來源**:mechanism R2-03;兩位稽核皆 pass,直接收錄;連鎖的驗收刻度改寫義務已在全清單落實。
- **對應問題**:S2 延伸(保守偏差完整性)。現制進場有不利滑價、出場零滑價——停損以停損價整數成交(broker.py:80)、強平以收盤整數成交,摩擦被系統性低估,違反「模擬寧可低估不可高估」。
- **修訂內容**:沿用現有滑價參數(2 pips / 2 點,是否另設見 D-08)套用於出場:stop 出場價 = stop ∓ 滑價(不利方向)、invalidated 出場價 = 收盤 ∓ 滑價;target 出場維持以目標價成交(限價單性質,不加有利滑價)。r_multiple 以含滑價實際出場價計算,停損單將略差於 −1.0R,照實入帳。**連鎖義務**:全清單所有「停損恰 −1R / 實虧恰 1%」類驗收統一改寫為「r = −(1+出場滑價/停損距離)、實虧 = 資本×1%×(1+出場滑價/停損距離)」(R2-02 門檻下實虧上限 1.1%)——R2-01、R2-07 驗收已依此改寫,避免三套 AC 互相矛盾。
- **驗收條件**:
  - Given long 持倉觸及 stop=S / When 出場 / Then 出場價 = S − 滑價,r_multiple = −(1+滑價/停損距離)(誤差 <1%)且 < −1.0。
  - Given 觸及 target=T / When 出場 / Then 出場價 = T,與第一輪行為一致。
  - Given invalidated / Then 出場價 = 收盤價加不利方向滑價。
- **預期影響**:摩擦假設進出對稱、不再美化停損;與 R2-02 搭配後滑價占比有上限,不會重演 89.3% 吞噬。
- **風險/副作用**:兩輪 R 刻度定義不同(第一輪停損恰 −1R、第二輪略差於 −1R),報告對照須加註;絕不回改第一輪台帳。整體方向對自己更不利,無保守偏差之虞。
- **實作成本**:小(broker 出場路徑數行 + 測試)。

### R2-04 MAX_HOLD_BARS 週期相稱化(per-timeframe 字典)

- **來源**:mechanism R2-04;採稽核A修正版(補 planner 與 tests 改動點)。
- **對應問題**:S3。單一 MAX_HOLD_BARS=20 對 1d ≈ 4 週、對 1h 僅 20 小時(不到一個完整交易日),時間停損量綱對 1h 失真。開票依據是量綱錯誤本身,非該 2 筆「獲利中被強平」的結果(n=2 僅旁證)。
- **修訂內容**:
  1. config.py 改為 `MAX_HOLD_BARS = {"1d": 20, "1h": 120}`:1h 以外匯每週約 120 根交易時K計 ≈ 一個日曆交易週;刻意不取與 1d 等日曆的 ~480 根,避免長期占用 MAX_OPEN_PER_TRACK=2 曝險額度(取值見 D-03,定案後凍結);1d 值維持 20 不變。
  2. `broker._check_exit` 改查 pos.timeframe 對應值。
  3. 【稽核A補】`core/planner.py:62` invalidation 字串現以 `%d` 格式化純量,改 dict 會直接 TypeError——改為依 signal.timeframe 查 `MAX_HOLD_BARS[tf]` 後格式化。
  4. 【稽核A補】`tests/test_broker.py:76` 滿倉 fixture 同步改 per-timeframe 取值,並新增 1h=120 根 fixture。
  5. config 缺某 timeframe 鍵 → 明確報錯(KeyError 或啟動時驗證兩鍵齊備),防無聲回退。
- **驗收條件**:
  - Given 1h 持倉滿 120 根未觸發停損/目標 / When on_new_bar / Then 以收盤價(含 R2-03 出場滑價)出場、reason=invalidated。
  - Given 1d 持倉滿 20 根 / Then 行為與第一輪完全一致。
  - Given config 缺某 timeframe 鍵 / When 撮合 / Then 明確報錯而非默認值。
  - Given 任一 1d 與 1h 計畫 / When planner 產出 invalidation 文字 / Then 分別含 20 與 120。
- **預期影響**:時間停損回到「清理殭屍單」的設計原意,1h 趨勢單有存活空間;量測的是訊號而非量綱 bug。
- **風險/副作用**:延長 1h 持倉增加曝險額度占用、可能排擠新訊號(由 R2-08 的 exposure_cap 拒單計數監測);延長持倉理論上屬「對績效有利」方向——辯護=量綱一致性修正、數值出自設計推導(1 交易週)而非資料擬合,票面與報告聲明。【稽核B註】本票與 R2-02 同時改變 1h 取樣框,兩者效果在 1h 格內不可分離——因無確證假設孤立綁定 1h 可接受,但 prereg 定義 H1/H2 子集時必須先寫死週期組成(已納入 R2-10)。
- **實作成本**:小~中(config、broker、planner、tests)。

### R2-05 熔斷機制改造(事件落地+狀態可見;語義 A/B 案待裁決)

- **修訂內容(共通骨架,無論何案)**:

  3. 報告頁各軌風控狀態列、訊號層判定與風控核駁分欄(接 R2-08)。
  4. `DRAWDOWN_HALT = 0.10` 不放寬,prereg 明文禁止放寬(含「放寬到 15%」的誘惑)。
  5. 既有持倉照凍結規則走完(AC-13 語義不變);零隨機;PortfolioState 增熔斷狀態並持久化。

- **驗收條件**:

### 4.1 預註冊假設(詳 R2-10)
- **H1**:tech/pullback/short 平均 R > 0(第一輪 +0.362,n=7,資料挖掘假設)。
