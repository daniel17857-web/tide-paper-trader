## 1. 判定結論

### 1.1 resonance → 判 **(B) 門檻結構性過嚴**(規則在現行資料語意下結構性不可達;非 bug、非優先序抑制)

- **排除 (C)**:detect_range 全史重播 raw=0、live=0、suppressed=0;且 resonance 在 CHIP_PRIORITY 居首(resonance > zscore > streak,chip.py 註解與 rank 實作一致),結構上不可能被同軌訊號抑制。訊號在源頭就沒產生,與優先序無關。
- **排除 (A)(訊號層)**:三方獨立重算(主筆腳本、resonance 稽核之純 pandas 重算、momentum 稽核順帶重算)與 `signals/chip.py::_resonance_signals` 逐條件等價,皆重現 0 觸發;四子條件單獨運作正常(f↑ 27 / t↑ 22 / f↓ 24 / t↓ 29 天),資料無零值、無缺值(0/52),「外資及陸資」Item 已正確映射(adapters/taifex.py `_INST_MAP` 實測確認)。程式正確實作了文件化規則。
- **判 (B) 的核心事實**:致命閘是「當日同號」子條件——全史 52 日 foreign_net 天天 <0(-90,038~-74,081)、trust_net 天天 >0(+72,417~+85,325),同號天數 **0/51**。「雙雙同向增/減」交集其實有 11+13=24 天,只要同號偶爾成立 resonance 就會觸發;零觸發不是四條件疊加過嚴,而是同號閘全史 100% 失敗。資料語意為 TAIFEX `OpenInterest(Net)` 淨未平倉口數(adapters/taifex.py 檔頭文件化),在「外資結構性偏空、投信(ETF 避險)結構性偏多」的 regime 下,同號型規則**數學上必然恆零**,調任何門檻數值都救不了——此即「結構性過嚴」的定義,判 B。

**稽核衝突之裁決(依「可復算者為準」原則)**:三方所有可復算數字完全一致,**無數字衝突**;唯一衝突是 resonance 稽核將主因改判為「(A) 資料端 bug 嫌疑:高」(疑 trust_net 抓錯 Item/欄位),並主張 B 應予 refuted。裁決如下——**該 A 判不成立為既決判定,B 維持**,理由:

1. 稽核的 A 判依據「真實 TAIFEX 投信淨未平倉歷來僅外資一小部分且會變號」——此為**倉外經驗前提**,不可由 repo 內資料復算,且與近年正2/反1 ETF 規模化後投信台指期淨 OI 長期大額偏多的市場結構不符,前提本身可疑。
2. 稽核提出的分布特徵(恆正、CV 4.5%、量級鏡像外資、Δ相關 +0.016)**同樣完全相容於真實淨 OI 存量序列**:部位存量日變動本就平滑、慢變號;外資空單與投信多單互為對手盤則水準負相關(-0.73)而日變化近零相關是自然結果;稽核自己也承認「不是機械取負」。且 foreign_net 具有完全相同的「恆同號、平滑」特徵,稽核並未質疑 foreign_net——法醫證據對 trust_net 無鑑別力。
3. 三法人合計 mean ≈ -4,871 非人工零和(散戶為對手盤),反而支持資料真實性。
4. A 判自承「待一日原始 API JSON 比對定讞」——**未定讞之嫌疑不得作為判定**;本判定書判必須三選一且不得騎牆,依可復算證據判 B,並將 JSON 比對列為唯一翻案條件(見第 3 節)。momentum 稽核順帶重算亦獨立判 B,2:1 與可復算證據方向一致。

**翻案條件(明訂)**:抓取任一交易日 INST_ENDPOINT 原始 JSON,逐 Item 逐欄與 CSV 既存值比對;若 Item=「投信」該列之 `OpenInterest(Net)` 與 CSV trust_net 不符,本判定自動翻為 (A) 資料端 bug,並適用 D-06 bug 路徑(修復 + fixture 迴歸才可進第二輪)。比對相符則 B 定讞。

**附帶設計層備註(非本判定)**:若 F-03 規格原意為「當日淨買賣」而非「淨部位」,屬規格—資料語意錯配;就現行程式忠實執行文件化規則而言仍判 B。第三輪若要救 resonance,改的是規則定義(如改用淨額「日變化量」同號),不是門檻數值——屬規則變更,依 config.py 紅線視同重啟評估期。

### 1.2 momentum → 判 **(C) 觸發但被優先序抑制**(主因;熔斷風控與加掃採樣稀疏為輔;非 bug、非門檻過嚴)

- **排除 (A)**:raw=229 筆,momentum 稽核以獨立 pandas 向量化(ATR14=TR rolling(14).mean、EMA20=ewm(span=20, adjust=False)、前 20 根極值不含當根、n<21 不產訊)與 `signals/technical.py::detect_range()` 在全部 8 個序列**逐數 100% 吻合**(momentum raw 1/61/1/45/0/55/2/64;live 0/15/0/7/0/18/0/14),所有被抑制訊號 suppressed_by 均為 breakout。偵測器無 bug。
- **排除 (B)**:1.5×ATR 門檻在 1h 每對每月仍有數十筆 raw(全體 229 筆,約 0.75 根/日/對),門檻本身並不過嚴;降門檻只會放大 raw(1.25×→約 362、1.0×→約 601),救不了下述抑制結構。
- **判 (C) 的核心事實(票面假說成立)**:229 筆 raw 中 **175 筆(76.4%)同根 close 同時突破前 20 根極值,被 `TECH_PRIORITY = [breakout, momentum, pullback]` 系統性吃掉**——「大實體K往往同時突破 20 根極值」假說由三方與 D-11 四重驗證成立。1d 更是 **4/4 = 100% 被吃**,全史 1d 純 momentum 為 0,daily 模式即使每日全覆蓋也不可能成交任何 1d momentum。此同時解釋台帳 breakout 18 筆之高佔比。
- **輔因一(熔斷)**:live 54 筆中 22 筆落在 2026-09-01 技術軌 10% 回撤熔斷之後,依風控規則一律不可成交(台帳 tech 最後 entry 即 09-01,已復算確認)。
- **輔因二(採樣結構)**:熔斷前 live 32 筆中 18 筆早於 07-23 上線日(1h 資料回溯至 06-23),實盤窗內僅 14 筆;管線只對「執行當下最後一根K」偵測,1h 僅 london/newyork 兩個加掃時點,採樣率約 2/24,期望命中 ≈ 1.2 根,再過 planner RR≥1.5 與曝險上限後 0 成交。**8 週 0 筆是此設計在統計上的預期結果,無需任何 bug。**
- 結論:momentum 零成交是「過度決定」的——優先序吞噬(主因,C)+ 熔斷(C 之風控面)+ 加掃採樣稀疏(結構性配角)。三方判定一致,無衝突。

## 5. 限制聲明

1. **樣本窗短**:taifex_history 僅 52 個交易日(8 週)、fx 1h 約 16 週;「結構性」判定描述的是本窗 regime,窗外 regime 轉換(如外資轉偏多)可能使 resonance 自然復活,此為第二輪觀測項而非判定瑕疵。
2. **trust_net 真實性未定讞**:B 判以「CSV 資料忠實反映 API」為前提;該前提僅能以原始 JSON 比對確認(第 3 節翻案條件)。resonance 稽核引用之「投信 OI 歷來量級小且變號」為倉外經驗說法,無法由 repo 資料復算,本判定書未採為證據。
3. **下游未逐筆重播**:實盤窗 14 筆 live momentum 之未成交歸因於加掃採樣(2/24)與 planner 預檢(RR≥1.5、曝險上限),係依文件化排程與風控規則推算,未對 planner/broker 做逐筆撮合重播;惟三方推算一致且與台帳相容。
4. **並行變更**:調查期間另一 R2 實作程序修改了 config.py 與 core/*(R2-01~R2-08、D-01 A 案,mtime 15:06–15:09);signals/、data/、state/ 未被動過,被改鍵均非訊號偵測參數,且診斷兩次重跑 bit-identical,結果不受影響。本調查唯一新增檔案為 `scripts/diagnose_zero_trigger.py`(票面交付物,未 commit);D-11 重播腳本僅存於 scratchpad,未入 repo。
5. **零隨機性**:主筆腳本兩次重跑 diff 一致、D-11 兩次重跑 SHA 一致、兩份稽核均為確定性 pandas 重算;本判定書所有關鍵數字另由主筆對原始 CSV/台帳做第四次獨立復算核對,全數吻合,無未解數字衝突。

**判定總結(一句話)**:resonance 零觸發 = **(B) 結構性不可達**(同號閘 0/51,訊號碼正確、優先序無涉;附一次性 JSON 比對為唯一翻案條件);momentum 零成交 = **(C) 優先序吞噬為主因**(76.4% 被同根 breakout 吃掉,1d 100% 被吃)+ 熔斷與採樣稀疏為輔,訊號層無 bug。兩者依 D-06 均走「非 bug:保留、不調參、觀測」路徑,本輪優先序不動。
